# 場景作品：Scene／Stage

作品層把既有小型場景整理為可分享、可遊玩的內容。首版入口為桌面首頁及「遊戲 → 場景作品」，使用 Qt Widgets 製作、單人與 SmartAI 遊玩。它不提供線上上傳、多人闖關、局內精確續玩，亦未開放 XP／Android／Web／TUI 的作品介面。

參考來源為本機 `L:\无名杀-win32-x64\resources\app\mode\brawl.js`：單一 scene 與 stage 分存、有序場景、通關解鎖、接續與不攜帶玩家進度的匯出。此實作使用 QSanguosha 自身資料及執行流程，不執行無名殺的匯出 JavaScript。

## 製作與分享

| 資料 | 語意 |
|---|---|
| SceneDefinition | ID／修訂、標題、作者、簡介、開場／結尾文字、玩家席位、初始場景及目標 |
| StageEntry | 獨立關卡 ID，引用 scene 的 ID＋修訂；同一場景可重複編排 |
| WorkDefinition | 單場或多關作品、適用規則、依賴指紋、有序關卡、選關與繼承設定 |
| WorkProgress | 通關紀錄、續玩位置、歷史入口存檔；不放進分享檔 |

作品使用 schema 1 的 UTF-8 JSON，分享檔為 `*.qswork.json`。Stage 內嵌被引用的 scene 修訂，不依賴作者的絕對路徑。儲存在 `QSanRuntimePaths::userDataPath("scenario-works")` 下，作品及進度分開管理。ID 是身分，修訂是內容 SHA-256；改標題不會改 ID，編輯內容會產生不同修訂。

編輯場景使用既有 CustomAssignDialog；草稿的接受只回傳資料，不套用到全域自訂場景。Scene 修訂固定後，編輯會建立新修訂，已有 StageEntry 不自動追蹤變更；作者明確更新引用後再保存作品。失敗的讀取或驗證不取代原草稿。

匯入、匯出與進度寫入使用原子檔案替換。不同修訂並存，相同修訂可重複匯入。分享檔不含進度、Lua 腳本或圖音素材；擴展仍由既有安裝內容供應。

## 規則與相容性

目前僅支援 `mini_identity`：固定席位及身份、2–10 人、唯一玩家席位，其餘為 SmartAI。雙將由作品設定決定。遊玩暫時套用必要的單機設定，關閉房間後還原，不能將作品的規則寫入使用者一般模式設定。

未明確設定體力上限時，作品採場景武將的預設值；雙將取較低值，五人以上主公另加身份福利，不受一般對局的雙將體力方案影響。需要繼承體力但開局武將尚待選擇時，作者須明確設定可供驗證的體力上限。

作品保留既有實體卡編號，啟動前比對引擎版本、宣告的規則內容／擴展與牌表指紋。卡牌指紋包含順序及卡牌身分，不以卡牌總數相同代替相容。缺少依賴或指紋不相容時可匯入、查看及整理，但禁止開局。重新指定目前環境須由作者明確操作，再核對開局卡牌；不默默重綁匯入作品。

「所需擴展」列出作品綁定的宣告擴展名稱。首版採整個規則環境的精確相容性，這份清單不是自動推導出的最小依賴集合。

## 宣告式目標

每關可沿用 scene 目標，或明確指定關卡目標。成功、失敗各一組條件，每組選全部符合或任一符合；失敗優先。目標只由伺服器判斷，介面不從隱藏資料另算勝負。

| 條件 | 判斷 |
|---|---|
| alive／dead | 指定作者席位的存活或死亡狀態 |
| hp | 指定席位體力與常數比較 |
| mark | 指定席位的標記內部名稱與常數比較，缺少標記為 0 |
| turns | 玩家席位已完成的回合數；額外回合亦算一回合 |
| 比較運算 | `<`、`<=`、`==`、`>=`、`>` |

- **Objective**：成功條件不得為空，取代一般身份死亡勝負判定；在正常效果完成邊界檢查，先失敗、後成功。不得與舊場景強制結局條件混用。
- **Settlement**：按原本遊戲規則結束；玩家屬於勝方、成功條件符合且失敗條件不成立才通關。空成功條件表示沒有額外限制。
- 初始化完成即可符合的目標可能立即結束，作者應避免把單純「主角存活」當成唯一成功條件。
- 投降、平手、斷線中止及初始化失敗不通關。宣告式目標不等於任意 Lua 判定或完整自動化技能測試。

目標檢查放在正常完成的初始化／卡牌／傷害／回合等邊界，不能從標記 setter、解構函式或異常展開期間拋出 GameFinished。結算資料於清理技能、卡牌及房間前擷取，完成後只發出一次帶執行 ID 的結果。

## 跨關繼承與入口存檔

每個作品逐項啟用繼承，預設全關閉。

| 繼承項目 | 行為 |
|---|---|
| hp／maxhp／hujia | 過關時主角的體力、上限及護甲，覆蓋下一關相應初始值 |
| generals | 主副將；原生技能於新關重新建立 |
| hand／equip | 手牌、裝備的實體卡身分；不攜帶臨時變身、旗標或效果 |
| marks | 只帶入作者列出的標記名稱及數值 |
| skills | 作者白名單內、過關時額外持有的技能，下一關重新獲得 |

身份、敵人、判定區、私人牌堆、翻面、連環、技能實例 ID、用次與臨時效果不跨關。指定標記依作者清單處理，不推測技能的內部狀態。啟用繼承的關卡要求玩家席位存活才通關。

繼承資料先覆蓋下一關初始配置，再走正常初始化；繼承手牌時不追加設定中的開局摸牌，GameStart 技能仍正常執行。體力越界、重複卡牌、未知武將／技能或裝備容量衝突會阻止該入口開局，不靜默修值、複製卡牌或刪牌。

逐關模式按前關通關解鎖，已過關可重玩；自由模式可選任意關。正常接關使用本次成功結果。選關時可選原始配置或該關的歷史入口，預設最新入口；沒有歷史時使用原始配置。每次成功可建立新的不可變入口紀錄，失敗、取消及重試不覆寫原入口。未完成關卡離開後從選定入口重新開始。

進度綁定作品 ID＋修訂，更新作品另建進度。重複結果按 runId 去重。保存失敗時保留舊紀錄，結算畫面提供重試保存；成功保存及舊房間停止前不接下一關。

## 範例與驗收

空作品庫首次開啟時，依目前引擎解析卡牌並建立相容範例：桃回復教學、一回合擊破解謎、兩關短篇與苦肉狀態案例。範例不內建另一份牌表的卡號；缺少相應卡牌或技能時不生成該範例。

| 檢查點 | 驗證內容 |
|---|---|
| 資料與編輯 | 舊格式往返、失敗保留草稿、修訂固定、匯入匯出、翻譯鍵 |
| 單關執行 | 玩家席位映射、兩種目標、巢狀效果完成邊界、原有身份對局不受影響 |
| 進度與繼承 | 歷史入口、試玩隔離、重複结果、寫入失敗、卡牌／技能／容量衝突 |
| 完整作品 | 分享至相容環境、兩關通關、關閉後續玩、主客戶端及伺服器乾淨退出 |

`qsanguosha_scenario_work_tests` 是 Qt Core focused executable，CTest 註冊供遠端 CI 使用。本地不執行 CTest；targeted build／focused executable 仍須完成檢查點及取得授權。GUI 與完整對局另需人工驗收，不能以靜態檢查或建置代替。

`qsanguosha_core_tests --suite scenario-work-runtime` 提供開局准入、固定席位、目標條件與繼承資料的測試案例；完整對局的事件派發、結算與乾淨退出另行驗收。

當前實作輪次的建置、focused、GUI／完整對局與 CI 結果應分開回報；尚未執行者維持 NOT RUN。
