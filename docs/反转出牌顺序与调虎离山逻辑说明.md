# 反转出牌顺序与「调虎离山」逻辑说明

本项目已移植了「反转出牌顺序」功能，并针对「调虎离山」锦囊牌调整了玩家遍历逻辑。

## 1. 核心逻辑变更

### 1.1 玩家指向 (Linked List)
反转状态现在由 `RoomRoster` 类维护一个 `bool m_playOrderReversed` 变量（`src/server/room-roster.h:52`）。
- 当出牌顺序反转时，`RoomRoster::reversePlayOrder()` 切换状态并经 `relinkPlayers()` 遍历 `m_players` 列表、反向连接每个玩家的 `next` 指针（`src/server/room-roster.cpp:265-287`）。
- 反转操作会自动影响 `getNext()`、`getNextAlive()` 和 `getNextGamePlayer()` 的遍历方向。

### 1.2 调虎离山：不计入座次与距离
「调虎离山」的目标角色会调用 `setRemoved(true)` 标记为移除状态。
- **`ServerPlayer::getNextAlive(n)`**: 现在会额外跳过 `isRemoved()` 为 true 的玩家。
    - 影响范围：座次计算、距离计算、围攻 (Encircled) 判断、队列 (Queue) 判断。
- **`ServerPlayer::getNextGamePlayer(n)`**: **新增函数**。仅跳过阵亡玩家，忽略移除状态。
    - 理由：调虎离山的角色虽然不计入座次，但其回合逻辑（如回合开始、回合结束）仍需正常执行。

## 2. 代码实现细节

### ServerPlayer (serverplayer.cpp/h)
- 修正 `getNextAlive` 逻辑：`do next = next->next; while (next->isDead() || (next != this && next->isRemoved()));`
- 新增 `getNextGamePlayer`：保留原 `getNextAlive` 只跳过死者的逻辑。
- 新增 `getPreviousAlive` / `getLastAlive`：方便 Lua 端或 C++ 端双向搜索存活玩家。

### RoomRoster（room-roster.cpp/h）与 Room 委派（room.cpp/h）
反转状态与翻转逻辑现在由 `RoomRoster` 持有：
- `RoomRoster::reversePlayOrder()`: 切换 `m_playOrderReversed` 并经 `relinkPlayers()` 更新所有玩家的 `next` 指针（`src/server/room-roster.cpp:265-287`）。
- `RoomRoster::isPlayOrderReversed()`: 获取当前是否处于反转状态（`src/server/room-roster.cpp:272-275`）。
- `Room` 保留同名委派：`Room::reversePlayOrder()`（`src/server/room.cpp:4228-4237`）转调 roster 并发送反转/恢复日志；`Room::isPlayOrderReversed()`（`src/server/room.cpp:4239-4241`）转调 roster。

### RoomThread (roomthread.cpp)
- **`actionNormal`**: 翻到下一名玩家时改用 `getNextGamePlayer()`。
    - 确保调虎离山状态下的角色在轮到其回合时，引擎能正确定位到该角色。

## 3. 调试与指令

### 作弊指令 (Cheat Command)
新增了作弊指令 `S_CHEAT_REVERSE_PLAY_ORDER`。可以通过发送对应的作弊协议包来实时切换出牌顺序，方便测试。

### 翻译说明
建议在 Lua 端的翻译文件中增加以下条目：
- `"#ReversePlayOrder"`: "出牌顺序已反转"
- `"#RestorePlayOrder"`: "出牌顺序已恢复"

---
*注意：本功能修改了基础的玩家遍历逻辑，若在开发新技能时遇到座次相关的 Bug，请检查是否使用了正确的遍历函数（`getNextAlive` vs `getNextGamePlayer`）。*
