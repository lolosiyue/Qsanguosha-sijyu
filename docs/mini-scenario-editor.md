# 小型場景編輯器

小型場景仍使用 `CustomAssignDialog`（Qt Widgets）編輯與既有文字格式。它配置開局狀態，不是對局中途的完整狀態還原工具；小型場景與一般遊戲模式仍維持獨立註冊，參見 [遊戲模式結構化說明](GameModeStruct_重構說明.md)。

## 操作

| 區域 | 用途 |
|---|---|
| 左側玩家清單 | 選擇 2–10 名玩家中的一位；上下移動會連同武將、卡牌、標記、進階狀態與先手一起交換 |
| 卡牌分頁 | 手牌、裝備、判定牌與全局預設牌堆；卡牌選擇器支援名稱、內部名稱、編號及擴展包搜尋 |
| 玩家設定 | 主副將、身份、體力、勢力、翻面、連環、額外技能、摸牌數、先手及任意標記 |
| 進階狀態 | 初始護甲、五類裝備欄數量與判定區廢除 |
| 場景規則 | 人數、隨機身份、剩餘牌進棄牌堆，以及結局條件 |
| 底部操作 | 載入預設、載入檔案、另存及套用；取消不套用到遊戲 |

武將可按翻譯名稱、內部名稱、擴展包搜尋。額外技能輸入框的補全選項包含「翻譯名稱 [內部名稱]」，選定後按添加；輸入也會篩選已配置技能。

自訂標記使用實際內部名稱，毋須存在標記圖片。名稱不接受空白及 `, : * |`。數量範圍為 0–999999，明確設定的 0 也會存檔。初始護甲的「武將預設值」不寫覆寫值；0 表示明確設為零。

體力與體力上限可設為 1–999，未勾選時由既有場景規則決定。若明確設定上限，儲存時檢查體力不得超過該上限及舊有 `hpadj` 調整後的結果。沒有明確上限時，最終值仍取決於武將及伺服器規則。

## 格式及相容性

保留空格或 `|` 分隔欄位的舊格式，輸出統一使用空格。空白行與 `#` 開頭的註解可讀取，註解不會重存。未提供專用控制項的欄位（例如 `general3`、`hpadj`）及未知額外選項會保留；編輯器不保證這些擴充欄位的遊戲語意。

新檔統一使用 UTF-8。Qt5 的編輯器及執行端會識別合法 UTF-8，其他舊檔保留本機編碼解讀方式；Qt6 沿用 UTF-8 預設。含 BOM 的 Unicode 檔仍由 QTextStream 偵測。

| 欄位 | 格式 | 行為 |
|---|---|---|
| `hujia` | `hujia:2` | 覆寫武將初始護甲，包含明確的 0 |
| `marks` | `marks:counter*2,@example*0` | 依內部名稱設定標記；舊格式保留 |
| `equipArea` | `equipArea:0*2,1*0` | 指定欄位的格數，0 為廢除，1–99 為容量；未指定沿用原有值 |
| `judgeArea` | `judgeArea:0` 或 `judgeArea:false` | 廢除判定區；`1`／`true` 表示啟用 |

裝備欄編號為：0 武器、1 防具、2 防禦坐騎、3 進攻坐騎、4 寶物。多欄裝備依卡牌的 `getOccupyLocations()` 計算容量。加入裝備時，尚有容量就追加，容量不足才替換占用重疊欄位的舊裝備。修改欄位數量不會自動刪除已配置卡牌；若留下衝突，儲存會指出問題，需移除衝突卡牌或恢復欄位。

執行順序沿用原有開局流程：武將預設護甲 → `hujia` 覆寫 → 額外技能與標記 → 區域設定 → 配牌及摸牌 → `GameStart`。舊檔的 `marks:@HuJia*N` 因此優先於 `hujia`；在護甲控制項手動修改後會移除該舊護甲標記，留下單一來源。開局技能仍可繼續修改這些狀態。

範例：

```text
general:sujiang role:lord starter:true hujia:2 equipArea:0*2,1*0 judgeArea:0 marks:scenario_counter*2
general:sujiang role:rebel maxhp:6 hp:3
```

卡牌仍以目前引擎的實體卡編號儲存；既有卡名輸入會解析為可用實體卡。更換擴展包或牌表後，相同數字不保證代表同一張牌。預設牌堆沿用舊格式的反向儲存順序；手牌、裝備及判定牌讀取後維持檔案順序。

## 錯誤處理

載入先解析暫存資料，再檢查玩家數、武將、身份、先手、數字範圍、標記格式、卡牌重複與區域容量、互斥結局條件。失敗會顯示行號及原因，原本正在編輯的設定保留。保存使用 `QSaveFile` 原子替換；寫入失敗不破壞既有檔案。

支援一般身份陣營（主公、忠臣、反賊、內奸）。場景須有至少兩個陣營、至多一名主公、恰好一名先手。「本回合結束」與「下回合開始前」不可並用；牌堆耗盡結局需要預設牌堆。
