# H50P fallback SmartAI probes

`h50p_relationship_probe.lua` extracts the actual relationship methods (including
controller wrappers) from a supplied `smart-ai.lua`. It uses 50 fake players and
counts `objectName()` calls at the native boundary. It does not load packages or
simulate their native costs; its CPU timings are microbenchmark results, not turn
times. It checks dense-list replacement, sorting, removal, insertion, repeated
same-length mutation, equal-name wrappers, and changing/cyclic controllers.

From the runtime checkout:

```sh
git -C /workspace/extensions-src show 9fbaf64:ai/smart-ai.lua > /tmp/h50p-before.lua
lua tools/local/h50p_relationship_probe.lua /tmp/h50p-before.lua 100
lua tools/local/h50p_relationship_probe.lua /workspace/extensions-src/ai/smart-ai.lua 100
```

The optimized membership lookup validates positive positions against the live
list. Misses still scan: this avoids stale negative results when package AI edits
lists without going through `updatePlayers`. Controller relations remain live.
Positive hits are O(1); misses remain O(n), with the query name fetched once.

The first H50P comparison used the complete existing runtime package set, seed
26092891, `QSAN_LUA_PROFILE=1 QSAN_LUA_PROFILE_SEC=5 QSAN_AI_PROBE=1`, and:

```sh
QSAN_HEADLESS_PER_GAME_TIMEOUT=900 python3 -u tools/autotest/headless_runner.py \
  --exe /workspace/Qsanguosha-sijyu/debug/QSanguosha \
  --exe-root /workspace/Qsanguosha-sijyu \
  --log-dir /workspace/auto-games/runs/CHOOSE-A-NEW-DIRECTORY \
  --modes 50p --games 1 --parallel 1 --seed 26092891 --label h50p-profile
```

Set the three profiling environment variables above for that command. The runner
adds a 120-second startup allowance to its per-game timeout. Never reuse another
runner's directory. Copy source `ai/smart-ai.lua` to runtime `lua/ai/smart-ai.lua`
before launching; the runtime copy is ignored and must not be force-added.

```sh

python3 tools/local/h50p_profile_summary.py /workspace/auto-games/runs/h50p-20260928-codex-after
```

Summaries report timestamps, complete turn gaps, native decision probes, and Lua
sample totals. Only each sampling interval's top ten locations were logged, so
location totals are lower bounds. Instruction sample share is not wall time.
The original runtime's `SmartAI=50 fallback=0` startup message counts LuaAI versus
base C++ AI instances; it does not mean WorldView handled all decisions.

## H50P wave 2: mobile instance repair

`h50p_mobile_probe.lua` extracts the production repair helper and owner gate from
`nMobileEffect.lua`. It models the native 50-owner record loop, with a revision
change at each event and after the target writes a mark. Both revisions are
conservative: an unchanged event can reuse the preceding scan too.

```sh
lua tools/local/h50p_mobile_probe.lua /workspace/auto-games/runs/h50p-20260928-codex-h50p2-prof/nMobileEffect-before.lua 1000
lua tools/local/h50p_mobile_probe.lua /workspace/extensions-src/extensions/nMobileEffect.lua 1000
/tmp/h50p_lua54 tools/local/h50p_mobile_probe.lua /workspace/extensions-src/extensions/nMobileEffect.lua 1000
```

The last command uses the prior wave's repository Lua 5.4 driver (build recipe
in its RESULT.md). The probe checks missing instances after general changes,
removal, repair from a non-owner record, failed attachment retries, mutation of
an already scanned player during attachment, separate rooms with equal revisions,
roster growth, and the uncached path on engines without `aiStateRevision`.
The benchmark counts native-boundary lookups and Lua instruction samples, and
reports CPU time including the instruction hook. It is not an end-to-end game.

The repair cache is a weak room wrapper plus the native room revision and roster
count. The owner gate and all effects remain unchanged. A repair is never cached;
the next record verifies it. A complete scan stamps its *starting* revision so
any mutation during the scan forces another check. Missing revision API means
no cache. Collection of the weak wrapper also safely forces another scan.

Native invalidation audit at runtime `cf92cc39`:

- `Room::aiStateRevision` returns the room runtime's revision as a string (no
  Lua integer precision loss); it is already exposed in `swig/sanguosha.i`.
- `ServerPlayer` directly connects `skill_set_changed`, `general_changed`, and
  `general2_changed` to revision advancement. Instance creation/removal and
  detach-all in `Player` emit that signal. Mark, phase, and other state changes
  also invalidate conservatively.
- `RoomThread::dispatchV2` invokes records per current player instance. Repair
  stays before the owner early-out, so late-general repair timing is preserved.
- SWIG room wrappers compare by native pointer; the cache uses equality, not
  table-key identity. The weak reference does not keep a room wrapper alive.

The full-package A/B uses seed 26092892 and the same Lua/native profiling flags
as wave 1. Directories are `h50p-20260928-codex-h50p2-prof` and
`h50p-20260928-codex-h50p2-after` under `/workspace/auto-games/runs/`.
The summary now includes the recorded mobile-helper subtotal and percentage;
these remain lower bounds because each interval logs only its top ten locations.
Final observations, benchmark JSON, process status, and limitations are in the
after directory's `RESULT.md`. No distance semantics or package coverage changed.
Distance correction remains a separate hotspot: arbitrary package callbacks can
read marks/tags/cards, so a decision-scoped distance cache needs a broader audit
than just seats, horses, and fixed distance before it is safe to introduce.


## H50P wave 2c: definition vector only

`Engine::getDistanceSkills` now memoizes the ordered merged definition list per
room (or bootstrap engine). Both definition registries have registration,
replacement, rename and QObject lifetime versions. The cache checks both versions,
the exact Lua-definition exclusion set, and weak identities/names for every merge
dependency (including non-distance shadows absent from the result);
a changed stamp during filling prevents publication. Player roster and
`SkillSet::generation` do not affect this vector. All `correctDistance` callbacks
still run, in the original order; no distance/pair result is memoized.

`WrappedCard::adoptCard` emits `identityChanged` after a successful replacement.
RoomState wires its owned wrappers to that room runtime's revision, covering
`takeOver`, `copyEverythingFrom`, and `resetCard`. Initial construction and
same-inner-pointer no-ops do not bump. Equal printed names still bump because
new inner objects can have different behavior. Client room states have no
revision callback; the ClientPlayer distance path is unchanged.

The native regression is an explicit target excluded from normal builds:

```sh
/workspace/cmake-4.2.7-linux-x86_64/bin/cmake --build builds/cmake-linux-gui-gcc-debug --target h50p_distance_probe -j "$(nproc)"
builds/cmake-linux-gui-gcc-debug/h50p_distance_probe --asset-root /workspace/Qsanguosha-sijyu
```

It covers registry replacement/lifetime, non-distance shadowing, bootstrap/room
separation, callback execution, mid-fill mutation, exact exclusion/order checks,
registry clear, early destruction observers, and live equipped horse presence
with revision bumps on takeover/reset. It uses
native definitions without initializing game/AI VMs and exits after assertions;
it is not a worker shutdown test.

Seed 26092893 A/B artifacts are in `h50p-20260928-codex-h50p2c-prof` and
`h50p-20260928-codex-h50p2c-after` under `/workspace/auto-games/runs/`.
See the after directory's `RESULT.md` for measurements and run completion limits.
These changes do not establish safety for a pair-result distance cache: arbitrary
callback dependencies (including other card-state mutation paths) still require
separate proof before any such cache.

First comparable H50P2c activate (sgs37, seed 26092893): getDistanceSkills
290/48 ms → 290/14 ms; correctDistance 290/649 ms → 290/428 ms; activate
5065 ms → 3609 ms; distanceTo 145 → 145; distIter 55100/597 ms → 55100/410 ms.
The vector subtotal improved 70.8%; broader callback/activate wall variation on
the shared box prevents attributing the entire activate reduction to this cache.

## H50P AIWorldView / TriggerOrder throughput

`AiDecisionCoordinator` now shares its PublicBoard memo across events and decision
requests. Keys are room revision, global skill generation, room definition version,
and both ordered rosters. A mutation during filling prevents publication. Viewer
visibility, private state, event history and mode policy are still projected live.
TriggerOrder uses the existing event-only snapshot contract (no eager distances,
discard pile or event-history copy); other decisions retain their geometry. The
existing hidden/single-candidate handling and legacy fallback remain in place.

`tools/local/h50p_aiworldview_probe.cpp` tests the actual native coordinator with
50 seats, including revision/generation/definition/roster invalidation, mid-fill
mutation, event-history freshness and viewer isolation. In the final box probe,
50 uncached full views versus 50 TriggerOrder requests gave max-card callbacks
2500 → 50, distance callbacks 4900 → 0, and wall 6013 → 56 ms. This is a native
fixture without room extension Lua callbacks, not a 50p game-time claim.
The final binary also completed a full-package 02p game (seed 26092923), with
first UseCard 3.76 seconds after SmartAI initialization.

Artifacts and exact standalone compile/link recipes are under
`/workspace/auto-games/runs/h50p-20260929-codex-aiwv/`; build only
`qsanguosha_engine`, then use `compile-probe.sh` and `link-probe.sh`, and run
`worldview-probe --asset-root /workspace/Qsanguosha-sijyu`. Worker binaries were
linked to side paths; `debug/QSanguosha` was not replaced. Set
`QSAN_AI_WV_PROBE=1` to log public-board hits, build walls and publication guards.
See that directory's `RESULT.md` for the 50p runs (seeds 26092920–22), limits and
remaining hotspots. No extension source or gameplay skill semantics changed.

## H50P post-PublicBoard wave (aiwv-w2)

V2 instance records use an ownership index keyed by room lifetime, exact ordered
roster and SkillSet generation. Empty-owner definitions skip the owner loop;
other records query instance IDs only on possible owners. Attach/detach during a
callback disables filtering for the remaining owners, and IDs are still read
live at each owner. Nested dispatch retains a value snapshot of the candidate
set. No recordEvent, equipment record, triggerable, validity or effect is cached.
`RoomRoster::orderedFrom(..., true)` shares its unchanged rotation; alive-only
queries keep reading live alive flags.

TriggerOrder menus nested under GameReady (including InitialHandCards moves)
use the existing SmartAI policy directly, avoiding snapshot/facade creation.
This is an intentional startup policy fallback, not isolated coverage. The
ordinary single-choice shortcut, hidden-source consent and answer normalization
remain in PlayerDecisionService. Other events retain their configured route.
`QSAN_AI_WV_PROBE=1` logs each `trigger_order startup_legacy` call.

The native `tools/local/h50p_trigger_probe.cpp` fixture exercises the actual V2
record dispatcher, including in-callback attachments/removals, multiple copies,
empty-owner invalidation, nested rooms, roster changes, live alive flags, and
startup optional/mandatory AI decisions without a WorldView build. It exits
without worker teardown; use the real 02p smoke for lifecycle coverage.
Compile/link recipes, native output, side-worker runs and remaining stack
samples are under `/workspace/auto-games/runs/h50p-20260929-codex-aiwv-w2/`.
Build only `qsanguosha_engine` before running those side-link recipes; do not
replace an active soak executable. See that directory's RESULT.md for outcomes.
